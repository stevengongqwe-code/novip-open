# 本轮失败记录与处理

1. 批量图片累计输出限制：检查在加入结果数组之后可能把超额文件残留在成功队列。已改为先核对候选输出总量，再加入成功结果；失败项单独记录。
2. DOCX字体继承：不能把run中仅有ascii字体当作中文字体。改为分脚本继承；主题字体标未知。字体副本修复时移除冲突theme属性。新增专项回归已通过。
3. 计算空字段：空权重、空绩点字段、空单价不能默认变为0。已添加明确输入校验；统计/拟合及相对误差拒绝数值溢出。
4. OCR中文原始结果出现字间空格：例如“中 国 大 学 中 文 00123”。不偷偷当作完美结果；保留引擎原文供编辑。测试核对实际字符及00123，不宣称准确率；置信分不是实测准确率。
5. 新DOM测试最初把textarea或file input当普通input、照片页没有main标签、缺少createImageBitmap模拟，导致测试定位/运行失败。已修复测试环境与选择器；不是以跳过断言解决。最终实际下载断言均执行。
6. Native PDF回归曾因混用两套@napi-rs/canvas原生对象而发生测试进程段错误。统一使用PDF.js依赖的同一本地版本后，原28项转换检查通过。该问题位于Node测试替身，不作为浏览器已经验证的证据。
7. Android与桌面浏览器实际QA未执行：没有control-browser能力，不安装/启动未支持的替代浏览器。jsdom测试不验证视觉布局、输入法遮挡、真实手势缩放或手机保存到相册。
8. 部署包在跨工具读取时曾出现截断（gzip unexpected EOF），此前同站发布已用推送源码远程构建完成。若本轮再次出现，将保持同一项目和同一commit使用远程构建，不删除字体或OCR资源凑包、不声称损坏包有效。

9. 清空后重新选择同一DOCX/OCR图片：已重置原生文件选择器value并单独显示所选文件名，避免浏览器不触发同文件change事件；实验计算清空同时清除旧真值/吸光度，会员成本重置周期数。


## 本轮修复与未验证（NOVIP）
