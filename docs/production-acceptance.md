审计日期：2026-10-16（Asia/Shanghai）。正式域名：https://novip.site 。原地址：https://zhijian-handwrite.stevengongqwe.chatgpt.site/ 。基线为原项目 V12，commit `fa130d8cd66befca974780e573cbeb7a3479aa9d`。本轮65组单元测试、16个全套QA命令均通过，真实验收包16组专项通过，另有29份产出经独立库重开。本报告是源码与发布候选验收记录；实际发布版本与发布后HTTP状态以最终交付回执为准。

沿用现有 React19 / TypeScript / Vite6 静态站，PDF.js、pdf-lib、jsPDF、DOCX/PPTX生成库、SheetJS、fflate、Tesseract本地文件处理架构。没有重新建站。原16工具及新增入口共22项保留；原Logo、红黑白主题、作者微信StevenGRK、原域名配置、访问范围保持原样。

## A. 已复现问题与修复

### BUG-01 / P1：合法XLSX被误报为非普通工作簿

- 功能：Excel合并、Excel/CSV清洗。
- 复现：上传验收包07_excel_formulas.xlsx，原版报“工作簿主类型不是普通XLSX”。
- 根因：预检只接受 `[Content_Types].xml` 中对 `/xl/workbook.xml` 的Override；未支持合法的Default xml内容类型声明。SheetJS与独立解析器可读取原文件。
- 代码：src/sheets/core.ts，preflightXlsx。
- 修复：先匹配主部件Override，无Override时再解析xml Default；仍要求普通XLSX类型，宏、外部工作簿、缺失公式缓存的拒绝规则保持。
- 回归：原始文件中文工作表“成绩与公式”正常读取，D2–D5缓存值10、21、20、51；真实Worker→UI→XLSX下载重开，连续清空/上传/合并两轮通过。输出明确为值模式，不保留或重算原公式；原文件及公式不修改。
- 证据：tests/production-bugs.test.ts、production-sheets-ui.mjs；bugs-before/after、final-pack-sheets-dom.log。

### BUG-02 / P1：扫描件与简历取消后仍触发旧文件下载

- 功能：扫描增强PDF、简历PDF导出。
- 复现：在异步图片编码尚未完成时点“取消/重置”或“清空个人信息”；原版随后仍下载取消前的PDF。测试可控地延迟真实Canvas编码回调，无假下载/假成功。
- 根因：副作用下载发生在useJob回调内部，任务世代检查只在整个action返回后执行；已取消任务仍能在action内调用下载。
- 代码：src/tools/Scan.tsx、text-core.ts、Academic.tsx。
- 修复：将取消检查贯穿字体准备、分页编码与最终保存前；旧任务在下载前终止，不再触发已清空内容下载。
- 回归：扫描/简历两个复现路径均从“取消后下载1份”变为0份；正常导出与文件重开仍通过。
- 证据：tests/production-cancel-ui.mjs；cancel-baseline.json / cancel-after.json、final-cancel-dom.log。

### BUG-03 / P2：Office共享ZIP解析校验不足

- 复现：原zipEntries接受带`../`、反斜杠路径或重复/不一致文件名的包；损坏内容缺少显式CRC复核。
- 根因：此前主要检查中央目录解压大小后直接unzip，未核对本地目录、路径、重叠区域、名称唯一性与CRC。
- 代码：src/conversion/files.ts。
- 修复：解压前校验EOCD、单卷/支持压缩方式、中央与本地目录、名称、范围、路径、重复项与20MB/80MB限制；解压后核对数量、实际长度与CRC。
- 回归：恶意路径、名称不一致、重复、CRC损坏、目录大小矛盾均拒绝；全部合法PDF/Office/表格用例继续通过。
- 边界：这是输入校验加固，未发现或宣称已发生服务器路径写入、跨用户泄漏或远程执行。浏览器未开放通用ZIP解压服务。
- 证据：production-bugs.test.ts、final-unit.log、实际Office输出独立重开。

### BUG-04 / P2：材料规则JSON提示不友好、像素允许小数

- 复现：导入缺少闭合括号的JSON得到英文SyntaxError；宽度480.5被解析接纳，后续检查无法合理通过。
- 根因：JSON.parse异常未转换，像素字段只验证有限非负数。
- 代码：src/tools/materials-core.ts。
- 修复：给出中文JSON格式错误说明，并要求像素宽高为整数；已有字段白名单与大小限制保留。
- 回归：无效JSON和小数像素明确拒绝，正常导入导出规则仍可用。

### BUG-05 / P2：损坏PDF在报名材料中仍显示真实格式通过

- 复现：验收包损坏PDF具有PDF文件头，原材料检查显示格式通过（虽然旁注说不保证结构）。
- 根因：PDF仅按头部签名判断，而图片已完整解码。
- 代码：src/tools/materials-core.ts。
- 修复：PDF格式项先实际解析结构与页数；损坏、加密或超过50页时明确不通过/无法检查，像素/背景等仍保留人工复核，不把报名检查当官方认证。
- 回归：损坏样本由通过变为不通过；有效3页PDF及固定尺寸照片继续通过。

### BUG-06 / P2：PPT瘦身没有拦截伪装成PPTX的宏文档

- 复现：将验收PPTX内容类型改为MacroEnabled或加入无可执行代码的ActiveX测试部件，原瘦身检查仍接受；通用转换器此前会拒绝这类文件，两个入口策略不一致。
- 根因：独立瘦身模块只验证主要ZIP部件和签名，未复用宏/ActiveX类型限制。
- 代码：src/tools/ppt-core.ts，inspectPpt。
- 修复：在处理媒体之前拒绝MacroEnabled内容类型、VBA与ActiveX部件；提示另存无宏副本。普通嵌入对象仍按既有策略保持，不宣称对所有嵌入内容做安全认证。
- 回归：production-bugs.test.ts先失败后通过；普通PPTX压缩与结构/非媒体保留测试继续通过。未发现或宣称本网站实际执行了宏。

未发现经复现确认的P0问题；这不是“100%安全”或所有输入均无缺陷的保证。

## 安全、隐私与依赖

- 当前前端处理原始文件与正文，代码审计仅发现主动选择且已配置的Office保真后端具有文件POST；该保真模式在本部署未配置、UI禁用。没有添加文件上传服务、公共文件查询API或云端个人文件记录。
- localStorage仅存最近工具ID；OCR模型可缓存于浏览器，文件处理结果与输入留在页面内存。用户主动下载、复制、分享的内容由操作系统/接收方处理，本站不能承诺“绝不保存”。不同页面保留内存状态是既有功能，重置/刷新按工具清理；没有删除用户数据。
- DOM回归中受测文件/数据流程fetch/XHR/beacon为0，但未做真实浏览器Network抓包。无法据此覆盖浏览器、扩展、操作系统和未配置的外部后端。
- 文件类型/大小/页数/像素、Office宏与外部资源、DTD/实体拒绝规则保留。ZIP新增目录/CRC校验。界面采用React文本转义，未发现dangerouslySetInnerHTML或向日志上传文件正文的业务代码；恶意文件名不作为HTML执行。
- 本轮npm audit报告0条已知漏洞；npm ls正常。仅表示当次注册表审计覆盖范围，没有升级依赖来掩盖问题。锁定@xmldom/xmldom为0.8.15，对照官方已修复版本；本地vendor SheetJS为0.20.3。vendor/原生QA组件、未知漏洞、浏览器本身不因audit=0而保证安全。
- 独立Office后端源码保留但未部署/改配置。未做数据库迁移、数据删除、DNS/WAF/域名绑定变更，也未修改Graybird。

依赖核验参考：[npm audit官方说明](https://docs.npmjs.com/auditing-package-dependencies-for-security-vulnerabilities/)、[xmldom官方安全公告](https://github.com/xmldom/xmldom/security/advisories/GHSA-8344-3jmq-59r6)。

### 未嵌入中文字体的额外视检

原生PDF图片虽然可解码，首次视检却发现未嵌入的STSong中文缺字。排查确定原生测试主机缺少PDF.js使用的STSongStd回退字体；在QA环境注册已安装且有许可的Noto Sans SC为该系统字体回退后，中文和标点恢复，输出又经真实OCR检验“合法的中文”，没有修改原PDF或降低文件内容标准。该修正属于测试环境，未冒充生产修复。产品另补充未嵌入字体依赖本机回退、缺字时应嵌入字体重导出的提示。浏览器/安卓字体回退仍待实机，不能把可打开文件等同于内容完全正确。
